# ADR-0003: 이메일 발송 공급자 결정

- 상태: 제안됨 (조합 검토 대기)
- 작성일: 2026-09-17
- 근거 문서: ADR-0002(인증 방식) §"확정되지 않은 항목", `docs/planning/04-신규시스템통합-개발기획서-v1.0.docx` §14 "인증 방식은 접근성과 현재 공급자 비용을 확인한 뒤 결정"

## 배경

ADR-0002는 1차 인증 수단으로 이메일 매직링크를 선택했다. 이 방식에서는 이메일 발송이
곧 로그인 그 자체이므로 — 링크가 도착하지 않으면 아무도 로그인할 수 없다 — 발송
안정성(전달률)이 비용보다 먼저 고려해야 할 요소다.

## 검토한 대안

| 후보 | 방식 | 비용(2026-09 기준 조사) | 비고 |
|---|---|---|---|
| Resend | 관리형 트랜잭션 이메일 API | 무료: 월 3,000통(일 100통 상한). Pro $20/월 5만통, $35/10만통 | 도메인 인증만 하면 바로 발송 가능. 사용량 기반 과금(계정 수 무관) |
| AWS SES | 관리형 이메일 API | $0.10/1,000통(약 0.0001달러/통). 신규 계정은 크레딧만 제공, 기존처럼 월 3,000통 상시 무료는 2025-07-15 이후 계정엔 없음 | 신규 계정은 기본적으로 "샌드박스" 상태라 인증된 주소로만 발송 가능 — 프로덕션 전환 심사를 별도로 신청해야 함 |
| 자체 SMTP(Postfix 등) | 완전 자체 호스팅 | 인프라 비용만 | SPF/DKIM/DMARC, IP 평판 관리를 직접 해야 하며, 신생 발신 IP는 스팸함으로 분류되기 쉬움 |

## 결정

**R1은 Resend를 이메일 발송 공급자로 채택한다.**

이유:

1. **로그인 안정성이 최우선이다.** 매직링크가 스팸함에 들어가거나 지연되면 곧바로
   "로그인 불가"가 된다. 자체 SMTP는 발신 평판을 갓 시작하는 도메인에 불리해 이
   위험을 R1 시점에 감수할 이유가 없다(ADR-0001의 "자체 호스팅 우선" 원칙은 핵심
   업무 데이터에 적용한 것이며, 발신 평판처럼 시간이 필요한 자산까지 지금 자체
   구축하라는 뜻은 아니다).
2. **비용은 사용량 기반이라 ADR-0001의 "좌석 비용 없음" 원칙과 맞는다.** 시범
   규모(8~12명)와 R1 예상 물량(조합원 최대 수백 명이 로그인할 때만 발송)은 무료
   티어(월 3,000통) 안에서 충분히 소화된다.
3. **AWS SES 대비 착수 마찰이 적다.** SES는 신규 계정이 샌드박스 상태로 시작해
   "프로덕션 액세스" 심사를 별도로 통과해야 임의의 수신자에게 보낼 수 있다 — 개발
   착수 시점에 이 심사 대기시간이 R1 일정(2026.10~12)에 불필요한 지연을 만든다.
4. **전환 비용이 낮다.** 매직링크 발송은 애플리케이션 코드에서 이메일 API 한 곳만
   호출하는 얇은 계층(`src/lib/email/`)으로 감싸 두므로, 물량이 늘어 AWS SES가
   유리해지는 시점에도 공급자만 교체하면 된다 — 데이터는 우리 DB(`LoginToken`,
   `Session`)에 있고 Resend는 발송 경유지일 뿐이라 벤더 락인이 없다.

## 트레이드오프

- Resend는 프로프라이어터리 SaaS다. ADR-0001의 "벤더 락인 최소화" 원칙과 완전히
  일치하지는 않지만, 이메일 발송은 핵심 업무 데이터가 아니라 전달 경로이므로 락인
  범위가 좁다(위 "전환 비용" 참고).
- 무료 티어는 일 100통 상한이 있다. 초대를 대량으로 한 번에 발송하는 경우(예: 조합원
  전체 전환) 이 상한에 걸릴 수 있다 — 그런 대량 발송은 배치로 나누어 처리한다.
- 물량이 늘어 월 비용이 유의미해지면(Pro $20/월 이상) AWS SES로 전환을 재검토한다.
  전환 기준은 "월 발송량이 Resend Pro 요금제($20/5만통)보다 SES가 더 저렴해지는
  지점"으로 잠정 설정한다.

## 확정되지 않은 항목

- 실제 발신 도메인(SPF/DKIM 설정)과 발신 주소 — 조합의 실제 도메인이 정해지면 확정.
- Resend 계정 소유권 — 조합 명의 계정으로 생성해야 하며 개인 계정에 결제 수단을
  묶지 않는다(ADR-0001 §3.5 "조합이 확보할 것" 원칙).

# ADR-0004: 첨부파일 저장소 — R1은 로컬 디스크로 임시 착수

- 상태: 임시 결정 (R2에서 재검토 예정)
- 작성일: 2026-09-17
- 근거 문서: ADR-0001(기술 스택) "S3/MinIO 연동은 실제 요구사항이 확정되지 않은 채
  먼저 만들지 않는다"는 원칙, `docs/design/project-structure.md` "아직 없는 것" —
  첨부파일 업로드 항목

## 배경

`Attachment` 모델(기여 증빙, v0.1 A06 "수행 내용/증거")은 R1 스키마 설계 때부터
있었지만, 실제 파일을 어디에 저장할지(S3/MinIO 등 객체 스토리지)는 조합이 아직
결정하지 않았다. ADR-0001은 이 결정을 미루기로 했었는데, 첨부파일 업로드 화면
자체를 계속 안 만들면 "증거 없는 자가신고"(v0.1이 명시적으로 허용하는 것)만
가능한 채로 남는다.

## 검토한 대안

| 후보 | 방식 | 비고 |
|---|---|---|
| S3 호환 객체 스토리지(AWS S3/MinIO) | 관리형 또는 자체 호스팅 객체 스토리지 | ADR-0001이 이미 "결정 보류"로 남긴 항목. 조합 명의 계정·버킷 정책 등 확정할 것이 많아 R1 착수를 막고 있었다 |
| 로컬 파일시스템(서버가 도는 디스크에 직접 저장) | 애플리케이션 서버 프로세스가 파일을 직접 읽고 쓴다 | 별도 계정·과금·네트워크 설정이 필요 없어 지금 바로 쓸 수 있다. 서버를 여러 대로 늘리면(수평 확장) 각 서버가 자기 디스크만 보므로 안 맞는다 |

## 결정

**R1은 로컬 파일시스템에 첨부파일을 저장하고, 다운로드는 반드시 인증을 거치는
API 라우트(`/api/attachments/[id]/download`)로만 제공한다.** 저장 위치는
`ATTACHMENT_STORAGE_DIR` 환경변수로 바꿀 수 있고, 기본값은 프로젝트 루트의
`storage/attachments/`다(`.gitignore`에 등록해 실수로 커밋하지 않는다).

이유:

1. **지금 결정하지 않으면 계속 미뤄진다.** S3/MinIO 계정·버킷·자격증명은 조합이
   확보해야 하는 항목(ADR-0001 §3.5)이라 이 프로젝트 혼자 정할 수 없다. 그 결정을
   기다리는 동안 "증거 있는 기여"를 아예 못 남기는 것보다, 갈아끼울 수 있는 얇은
   추상화 뒤에서 로컬 저장으로 먼저 기능을 제공하는 편이 낫다.
2. **DB 스키마는 이미 스토리지 불가지론적이다.** `Attachment.fileKey`는 "저장소
   안에서 이 파일을 찾는 키"일 뿐 URL이 아니다. 저장 방식을 바꿀 때 스키마
   마이그레이션 없이 `src/lib/attachment-storage.ts`(읽기·쓰기 함수 2개)만
   S3 SDK 호출로 바꾸면 된다 — Resend 이메일 공급자를 얇은 계층으로 감싼 것과
   같은 원칙(ADR-0003 참고).
3. **`public/`에 두지 않고 인증 라우트로만 제공한다.** Next.js의 `public/` 폴더는
   누구나 URL만 알면 접근할 수 있다. 기여 증빙은 v0.1 P01이 "제한 필드"로 분류한
   것과 같은 민감도라, 로컬 저장이라도 접근 제어 없이 두면 안 된다고 판단했다.

## 트레이드오프

- **수평 확장 불가**: 서버 프로세스를 두 대 이상 띄우면(로드밸런서 뒤) 파일을 올린
  서버와 다운로드를 처리하는 서버가 다를 수 있어 깨진다. R1은 단일 서버 운영을
  전제한다(ADR-0001). 여러 대로 늘릴 계획이 서면 이 결정을 먼저 재검토해야 한다.
- **백업 정책이 없다**: DB는 별도 백업 대상이지만, 이 디렉터리는 지금 백업 계획에
  포함돼 있지 않다 — 서버 디스크가 손상되면 첨부파일만 유실될 수 있다.
- **바이러스 검사 없음**: 업로드된 파일을 그대로 저장한다. 허용 MIME 타입을
  이미지·PDF로 좁혀 위험을 줄였지만, 악성 콘텐츠 검사는 하지 않는다.

## 확정되지 않은 항목

- 실제 객체 스토리지 공급자(S3 vs MinIO vs 다른 대안)와 그 비용·계정 소유권 —
  ADR-0001이 미룬 항목 그대로. 조합이 결정하면 이 ADR을 대체한다.
- 첨부파일 보존 기간·삭제 정책 — 지금은 소프트 삭제(`deletedAt`)만 하고 실제
  파일은 디스크에 남긴다.

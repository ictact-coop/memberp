# ADR-0001: 기술 스택 및 호스팅 방식 결정

- 상태: 제안됨 (조합 검토 대기)
- 작성일: 2026-09-16
- 근거 문서: `docs/planning/04-신규시스템통합-개발기획서-v1.0.docx` §1, §2, §10, §14

## 배경

기획서 v1.0은 다음을 개발 착수 전 확정해야 할 항목으로 명시한다(§14 "기술·호스팅": 운영 가능한 기술,
이전 가능성, 총비용 / R1 개발 전 확정).

핵심 제약:

1. 조합원 수가 늘어도 "편집자 좌석 비용"으로 참여를 제한하지 않는다 (§1).
2. 개발·운영 인력은 주담당 1명 + 보조 1명 수준이다 (§14, v0.2 §6.2).
3. 금액·배부·정산은 부동소수점 없이 정확히 계산되고 트랜잭션으로 보호되어야 한다 (BR-11, F02~F04).
4. 데이터·소스코드는 조합이 소유하며, 다른 운영자로 이전 가능해야 한다 (v0.2 §3.5, §1).
5. 모바일 웹(360px) 우선, 별도 네이티브 앱은 초기 범위에서 제외한다 (§2, §10).
6. 성능 목표는 계정 1,000 / 기여 10만 건 / 동시 사용자 20명 수준이다 (§10) — 대규모 트래픽 대응은
   불필요하다.
7. 파일은 비공개 기본, 권한 있는 다운로드만 허용해야 한다 (§10) — 정적 호스팅만으로는 불충분하다.

## 결정

| 계층 | 선택 |
|---|---|
| 애플리케이션 | Next.js (App Router) + TypeScript 단일 모놀리스 (화면 + API) |
| 데이터베이스 | PostgreSQL |
| ORM | Prisma |
| 인증 | Auth.js(NextAuth), 초대 기반 가입 + 이메일/전화 매직링크 또는 OTP |
| 파일 저장소 | S3 호환 오브젝트 스토리지 (자체 호스팅: MinIO / 관리형 대안: Cloudflare R2) + 서명 URL |
| 백그라운드 작업 | BullMQ + Redis (알림, Notion 이전 배치, 백업 트리거) |
| 배포 | 자체 VPS + Docker Compose (Next.js, Postgres, Redis, MinIO 컨테이너 + Caddy TLS 리버스 프록시) |
| 외부 연동 | Notion API(read-only) → 이전용 스테이징 테이블 → 검증 → 승인 후 반영 |

## 근거

- **모놀리스 단일 스택**: 별도 프론트/백엔드 분리는 배포 파이프라인이 2개로 늘어나 2인 체제의 운영
  부담을 키운다. Next.js 하나로 화면·API·SSR·PWA를 모두 처리한다.
- **PostgreSQL**: 정확한 수치형(`numeric`), 행 단위 트랜잭션, JSONB(활동 유형별 가변 상세 필드에 활용)를
  모두 지원한다. NoSQL은 청구/입출금/배부 간 정합성(BR-11 "배부 합계 ≤ 확정액")을 보장하기 어려워 제외했다.
- **자체 VPS + Docker Compose**: 관리형 서비스(Vercel + Supabase 등)는 초기 구축 속도가 빠르지만
  월간활성사용자(MAU)·함수 실행량 기준 과금 구조를 가진 경우가 많아 "좌석비로 참여를 제한하지 않는다"는
  원칙과 충돌할 여지가 있다. 고정 월정액 비용과 완전한 인프라·데이터 소유권을 우선해 자체 호스팅을
  기본값으로 제안한다.
- **파일 스토리지의 S3 호환성**: MinIO(자체 호스팅)로 시작하되 API가 S3와 호환되므로 이후 R2/S3로
  이전해도 애플리케이션 코드 변경이 없다.

## 트레이드오프 및 재검토 조건

자체 호스팅은 서버 운영을 맡을 인력이 필요하다. v1.0 §14 "개발·운영 담당"(주담당·대체담당 확보) 결정이
아직 확정되지 않았다면, 다음 절충안을 고려한다.

- R1(참여 시범) 단계만 관리형 서비스로 구축해 속도를 확보하고,
- R3(핵심 이전) 전에 자체 호스팅으로 이전한다.

이 경우에도 애플리케이션 계층(Next.js/Prisma/PostgreSQL)은 동일하게 유지되므로 마이그레이션 비용은
인프라 계층에 한정된다.

## 확정되지 않은 항목 (별도 결정 필요)

기술 스택과 별개로 다음은 조합의 의사결정이 필요하며 이번 ADR의 범위가 아니다 (v1.0 §14 참조).

- 인증 방식의 구체적 선택(이메일 vs 전화 OTP vs 소셜 로그인)과 계정 복구 절차
- 개발·운영 담당자 지정 (주담당/보조담당)
- 조합원 자격·사람 중복 판정 기준 명부
- 기여 확인 예외 규칙(본인이 본인 기여를 확인하는 소규모 예외)
- 개인정보 수집 범위·보존·삭제 정책
- 재무 처리 정책(승인 한도, 원천징수, 외부 회계 연결 방식)
- 이전 승인 권한자·복귀 책임자
- 공식 보고에 사용할 성과 지표의 확정 방식

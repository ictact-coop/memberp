# ADR-0002: 인증 방식 결정

- 상태: 제안됨 (조합 검토 대기)
- 작성일: 2026-09-17
- 근거 문서: `docs/planning/04-신규시스템통합-개발기획서-v1.0.docx` §3, §14 / `docs/planning/03-참여형시스템-병행운영전략-v0.2.md` §2.4
- 관련: ADR-0001(기술 스택) — Auth.js(NextAuth) 선택을 구체화한다

## 배경

기획서 v1.0 §14는 인증 방식을 "R1 개발 전" 결정 사항으로 지정하고, 권고 기준으로
"쉬운 사용과 계정 복구"를 든다. v0.2 §2.4는 다음을 이미 못박아 두었다.

- 초기 로그인은 초대 기반이다. 초대된 연락수단의 본인확인 후 기존 주체(`Subject`)와
  연결하며, 동명이인 자동 연결은 금지한다.
- 로그인 복구 경로를 마련하고, 임원·재무·운영 관리자에는 추가 인증을 요구한다.
- 최종 선택은 접근성과 현재 공급자 비용을 확인한 뒤 결정한다.

그 외 제약:

- FR-01 검수 기준: "만료 초대 사용 불가, 탈퇴·중지 계정 접근 차단" — 계정 상태 변경이
  **즉시** 반영되어야 한다.
- 조합원 다수가 개발자가 아니며, 모바일(360px) 우선으로 접근한다. 로그인 마찰이 크면
  §14 R1 사용성 목표(직접 입력 70% 이상, 기본 기록 80%가 2분 이내)를 못 채울 위험이 있다.
- ADR-0001의 "좌석 비용 없음" 원칙은 인증에도 적용된다 — 사용량 기반 과금은 허용하되,
  계정 수에 비례해 새로운 유료 좌석이 생기는 구조는 피한다.

## 결정

### 1. 1차 인증 수단: 이메일 매직링크(비밀번호 없음)

초대와 로그인 모두 "이메일로 1회용 링크 발송 → 클릭 → 세션 발급"으로 통일한다.
비밀번호 자체가 없으므로 "비밀번호를 잊음" 상태가 존재하지 않는다 — 복구는 항상
새 링크 재발송이다. 이는 §14의 "쉬운 사용과 계정 복구" 기준을 가장 단순하게 만족한다.

### 2. 전화번호(SMS OTP)는 R1에서 보류한다

`Account.phone` 필드는 스키마에 남겨두되(향후 연락 채널·본인확인 보조 용도),
SMS 기반 로그인은 R1 범위에서 제외한다. 국내 SMS 발송은 게이트웨이 계약과 문자 템플릿
사전승인 등 행정 절차가 필요해 §14가 요구하는 "현재 공급자 비용을 확인한 뒤 결정"
조건을 지금 충족할 수 없다. 시범운영에서 "이메일을 거의 안 보는 조합원" 비율이
유의미하면 R2에서 재검토한다.

### 3. 세션은 데이터베이스 기반으로 관리한다 (JWT 무상태 세션 사용 안 함)

무상태(JWT) 세션은 만료 전까지 서버가 개입할 수 없어 FR-01의 "탈퇴·중지 계정 접근
차단"을 즉시 보장하기 어렵다. 세션 레코드를 DB에 두고 매 요청마다 계정 상태
(`Account.status`)와 세션 상태를 함께 확인해, 사무국이 계정을 정지하면 그 순간부터
접근이 막히게 한다.

### 4. 임원·재무·운영 관리자는 TOTP 2단계 인증을 추가로 요구한다

`PermissionGrant.role`이 `BOARD`, `FINANCE`, `SECRETARIAT`, `SYSTEM_ADMIN`인 계정은
로그인(매직링크) 후 OTP 앱(TOTP) 코드를 추가로 요구한다. SMS 기반 2단계 인증은 쓰지
않는다 — TOTP는 외부 공급자 의존과 발송 비용이 없고, 이미 결정 2번(SMS 보류)과도
일치한다. 기기를 분실했을 때를 대비해 1회용 복구코드(발급 시 10개)를 제공한다.

### 5. 소셜 로그인(카카오 등)은 R1에서 채택하지 않는다

한국 이용자에게는 익숙하지만, 이메일 스코프 획득에 별도 비즈니스 인증 절차가 필요해
R1 일정(2026.10~12)에 맞추기 어렵고, 우리 시스템의 정본 식별자(이메일)를 외부
플랫폼 정책에 종속시키게 된다. 조합원 편의를 위한 "부가 로그인 수단"으로는 R2 이후
재검토할 수 있다 — 배제가 아니라 유예다.

### 6. Auth.js는 유지하되 커스텀 어댑터로 연결한다

ADR-0001에서 정한 Auth.js(NextAuth) 선택은 유지한다. 다만 Auth.js의 기본 Prisma
어댑터 스키마(`User`/`Account`/`Session`/`VerificationToken`)를 그대로 쓰지 않는다.
Auth.js의 `Account` 모델은 "OAuth 제공자 연결"을 뜻하는데, 이미 설계한 R1 스키마의
`Account`(로그인 자격 — `docs/design/r1-schema.md`)와 이름은 같지만 의미가 달라
혼동을 일으킨다. R1은 OAuth를 쓰지 않으므로(결정 5) Auth.js의 `Account` 테이블
자체가 필요 없고, `User`/`Session`/`VerificationToken`에 해당하는 개념만 우리
도메인 모델(`Subject`/`Account`) 위에 커스텀 어댑터로 얹는다.

## 트레이드오프

이메일을 거의 확인하지 않는 조합원에게는 여전히 진입장벽이 있다. 완화책:

- 로그인 후 세션을 길게 유지한다(기본 30일, 활동 시 갱신) — 매번 이메일을 열 필요는
  없고, 초대·최초 로그인 시점에만 마찰이 생긴다.
- 사무국이 초대·로그인 링크를 필요하면 대신 재발송할 수 있다.
- 시범운영(2026.12~2027.01)에서 "직접 입력 70%" 기준 미달의 원인이 이메일 장벽으로
  확인되면 R2 SMS 도입을 앞당긴다.

## 확정되지 않은 항목 (별도 결정 필요)

- 이메일 발송 공급자(Resend, AWS SES, 자체 SMTP 등)와 실제 비용 — ADR-0001 §3.5
  "인증·알림" 항목과 함께 확정한다.
- 세션 유지 기간의 정확한 값(30일은 제안값이며 조정 가능).
- TOTP 강제 대상 역할의 최종 목록(현재 BOARD/FINANCE/SECRETARIAT/SYSTEM_ADMIN 제안).
- 개인정보 처리방침상 이메일·전화번호 보유 기간 — v1.0 §14 "개인정보 정책" 결정에
  종속된다.
